# ADR-004 — Internacionalização (i18n)

> **Status:** Aceita
> **Data:** 2026-03-22
> **Autores:** Flavio

---

## Contexto

O MariPDF precisa suportar múltiplos idiomas, com PT-BR e EN embutidos no binário e outros idiomas disponíveis sob demanda (download via CDN). A solução deve ser leve, idiomática em Rust e permitir hot-swap sem reiniciar o app.

---

## Opções Consideradas

### Opção A — Mozilla Fluent ✅
- ✅ Criado pela Mozilla — usado no Firefox
- ✅ Suporta pluralização, gênero e seleção condicional nativa no formato `.ftl`
- ✅ Crate `fluent` estável para Rust
- ✅ Hot-swap de locale em runtime (trocar `FluentBundle`)
- ✅ Formato `.ftl` é legível por tradutores não-técnicos
- ✅ `sys-locale` para detectar locale do sistema (Windows API nativa)
- ❌ Formato `.ftl` menos familiar que `.po`/`.mo` do gettext

### Opção B — gettext (`gettext-rs`)
- ✅ Padrão da indústria em C/Linux, familiar para tradutores
- ✅ Ferramentas de edição maduras (POEdit, Lokalize)
- ❌ API Rust menos ergonômica
- ❌ Pluralização mais limitada que Fluent
- ❌ Dependência de runtime `.po`/`.mo` — compilar para binário estático é não-trivial
- ❌ Hot-swap complexo

### Opção C — `rust-i18n`
- ✅ API simples e macro-based: `t!("key")`
- ✅ Carrega de YAML — familiar
- ❌ Sem suporte a pluralização avançada
- ❌ Carrega **todos** os idiomas em RAM na inicialização
- ❌ Sem hot-swap nativa

---

## Decisão

**Escolhemos: Opção A — Mozilla Fluent**

O único sistema que combina: pluralização avançada nativa, hot-swap de locale, formato acessível a tradutores e suporte correto a variações linguísticas complexas (PT-BR tem diferenças do PT-PT). A curva de aprendizado do `.ftl` é baixa.

---

## Arquitetura de Implementação

### Arquivos bundled (embutidos no binário)

```rust
// i18n/mod.rs
const EN_FTL: &str = include_str!("../../locales/en.ftl");
const PT_BR_FTL: &str = include_str!("../../locales/pt-BR.ftl");
```

Esses dois idiomas estão **sempre disponíveis offline**, sem download.

### On-demand (outros idiomas)

1. Usuario muda para `es` (Espanhol)
2. App verifica `%APPDATA%/maripdf/locales/es.ftl`
3. Se não existe → download de `https://releases.maripdf.dev/locales/es.ftl`
4. Salva em cache local
5. Hot-swap: substitui o `FluentBundle` em runtime — sem reiniciar

### Detecção automática

```rust
// usa sys-locale para detectar o locale do Windows
let system_locale = sys_locale::get_locale()
    .unwrap_or_else(|| "en".to_string());
```

### Formato dos identificadores de mensagem

```fluent
# Formato: módulo-ação ou módulo-elemento
nav-page = Page { $current } of { $total }
toolbar-zoom-fit-width = Fit Width
toast-file-opened = { $pages ->
    [one] Opened — 1 page
   *[other] Opened — { $pages } pages
}
search-results = { $count ->
    [0] No results
    [one] 1 result
   *[other] { $count } results
}
```

---

## Consequências

- **Tradutores** precisam aprender o formato `.ftl` (simples, ~30min)
- Manter `en.ftl` como **fonte da verdade** — novos textos sempre vão lá primeiro
- `pt-BR.ftl` é obrigação do mantenedor principal manter em sync
- Para novos idiomas: abrir PR com o arquivo `.ftl` em `locales/`
- O build CI verifica que todos os IDs do `en.ftl` existem em `pt-BR.ftl`
